# Деплой на Railway (чтобы бот работал постоянно, 24/7)

## 1. Создать аккаунт
Зайти на **railway.app** → Login → можно войти через GitHub-аккаунт
(тот же, где лежит репозиторий `rep_cv`) — это самый простой способ.

## 2. Создать новый проект из репозитория
1. На главной странице Railway нажать **New Project**
2. Выбрать **Deploy from GitHub repo**
3. Если Railway попросит разрешение — разрешить доступ к GitHub
4. В списке репозиториев выбрать **rep_cv**

Railway сам обнаружит `Procfile` и `requirements.txt` и начнёт сборку.

## 3. Добавить токен бота (обязательно!)
Токен намеренно не хранится в коде (в `.env`, который не попадает в
GitHub) — поэтому Railway его не знает, пока вы не введёте сами:

1. Открыть созданный проект в Railway
2. Вкладка **Variables**
3. Нажать **New Variable**
4. Имя: `TELEGRAM_BOT_TOKEN`
5. Значение: токен от @BotFather (тот же, что мы уже использовали)
6. Сохранить

После сохранения Railway автоматически пересоберёт и перезапустит бота
с этим токеном.

## 4. Проверить, что бот запустился
Вкладка **Deployments** → открыть последний деплой → вкладка **Logs**.
Должны быть строки вида:
```
Bot starting (polling)...
Application started
```
Если видно ошибку — прислать мне текст ошибки, разберёмся.

## 5. Готово
Теперь бот работает сам по себе на сервере Railway — не зависит ни от
вашего компьютера, ни от этого чата. Можно закрывать ноутбук, выключать
его — бот продолжит отвечать в Telegram.

## Известное ограничение (пока не критично)
Ключевые слова, CV и список уже показанных вакансий хранятся в файле
(SQLite) прямо в контейнере Railway. Это переживёт обычную работу
бота, но **при пересборке/редеплое проекта данные могут сброситься**.
Если это станет проблемой — можно подключить постоянное хранилище
(Railway Volume), но это отдельный шаг на будущее.
